DNS & AdGuard

AdGuard Home acts as the recursive resolver for all homelab VLANs. It handles ad-blocking, DNS rewrites for internal services, and upstream forwarding to public resolvers.

AdGuard Home DNS rewrites

01 Overview

All VLANs on the UDR7 point to AdGuard Home as their DNS server. This gives a single control plane for:

  • Ad & tracker blocking — filters applied to all VLANs equally.
  • DNS rewrites — internal hostnames (e.g. argo.in.alybadawy.com) resolve to the k3s server IP without leaving the LAN.
  • Upstream forwarding — all other queries forwarded upstream over .

02 DNS rewrites for cluster services

All *.in.alybadawy.com hostnames resolve to the k3s server's IP address on the LAN. Traffic never leaves the network for internal services — it hits the ingress-nginx controller directly.

# Examples of what resolves:
argo.in.alybadawy.com      →  k3s server
vault.in.alybadawy.com     →  k3s server
grafana.in.alybadawy.com   →  k3s server
auth.in.alybadawy.com      →  k3s server
cloud.in.alybadawy.com     →  k3s server
photos.in.alybadawy.com    →  k3s server
Why Cloudflare CNAME records still exist. The in.alybadawy.com subdomain has CNAME records in Cloudflare pointing to alybadawy.com (unproxied). These are needed so cert-manager's DNS-01 ACME challenge can create _acme-challenge.in.alybadawy.com TXT records that Cloudflare's DNS actually serves. Without them, Cloudflare's DNS wouldn't serve child TXT records. External DNS for in.alybadawy.com is intentionally a dead end — the services are LAN-only.

03 Blocklists

AdGuard Home applies blocklists to all VLANs. The IoT and Guest VLANs benefit most — devices on those networks cannot make DNS queries that bypass AdGuard (the UDR7 firewall intercepts and redirects port 53 traffic).
