VLAN segmentation

Ten VLANs on the UDR7, each with a defined trust level. The 172.20.Y.Z addressing scheme makes every IP self-documenting — the third octet is the VLAN ID.

10 VLANs 172.20.Y.Z scheme zone-based firewall

01 IP addressing scheme

All homelab networks (except AREDN node LANs) use 172.20.Y.Z:

  • 172 — RFC 1918 private range
  • 20 — site identifier (this homelab)
  • Y — VLAN ID and network designator (same number)
  • Z — host address

This means you can read any IP and immediately know which VLAN it's on. 172.20.100.15 = VLAN 100 (IoT), host 15. No lookup required.

AREDN exception. AREDN node LANs use their own mesh-assigned ranges (e.g. 10.6.229.8/29). These are assigned by the AREDN network and not under local control.

Future AREDN nodes will use VLANs 43, 44, etc., each with their own node-assigned LAN range. The DtD VLAN 41 is reserved for direct device-to-device mesh links when needed.

03 Trust hierarchy

VLANs form a tiered trust model enforced by the UDR7 zone-based firewall:

TierVLANsAccess
Trusted Personal (10), VPN (30) Can reach Servers. Can reach internet. Can access self-hosted services.
Infrastructure Servers (20), Management (1) Servers can be reached by Trusted. Management is admin-only.
Restricted IoT (100) Internet access only. Selective outbound to specific Servers IPs (e.g. Home Assistant). No inbound from other VLANs.
Isolated Guest (200), Work (210) Internet only. No access to any local VLANs. No inter-device communication.
Mesh AREDN-WAN (40), AREDN-Node1 (42) AREDN mesh traffic. Isolated from all other homelab VLANs.
