# GitOps Architecture & App of Apps Pattern

## Overview

This document explains the GitOps infrastructure and the App of Apps pattern used to manage all cluster applications through a single source of truth: the git repository.

## What is GitOps?

GitOps is a methodology where:
- **Git is the source of truth** — All cluster state is defined in git
- **Declarative configuration** — Infrastructure is described as code
- **Automated reconciliation** — Tools continuously sync cluster state to match git
- **Version control** — Changes are tracked, auditable, and reversible

In our setup, **ArgoCD** is the GitOps operator that watches the repository and synchronizes cluster state.

## App of Apps Pattern

The App of Apps pattern is an ArgoCD best practice where:
- A **root Application** manages other Applications
- Each child Application can deploy a microservice, infrastructure component, or group of related resources
- This creates a hierarchical, manageable structure for complex deployments

### Architecture Diagram

```

```

## Deployment Flow

### Phase 7: Bootstrap Process

1. **Nginx-ingress installed** (prerequisite via Helm)
   ```bash
   helm install nginx-ingress ingress-nginx/ingress-nginx \
     --namespace ingress-nginx \
     --values git-ops/nginx-ingress/values.yaml
   ```

2. **ArgoCD namespace created**
   ```bash
   kubectl create namespace argocd
   ```

3. **Bootstrap Application created** (via kubectl)
   ```bash
   kubectl apply -f bootstrap-app.yaml
   ```
   This Application points to: `https://github.com/AlyBadawy/hl-beta` → `git-ops/root-app`

4. **ArgoCD reconciliation loop starts**
   - ArgoCD detects new Application
   - Fetches root-app Helm chart from git
   - Deploys root-app to cluster

5. **Root-app creates child Applications**
   - root-app Helm chart generates Application manifests
   - argocd-app.yaml → ArgoCD manages itself
   - nginx-ingress-app.yaml → Nginx-ingress updates managed by Argo
   - git-config-cm.yaml → ConfigMap with repo URL for all apps

### Normal Operation: Git to Cluster Sync

```
Developer commits to git
        ↓
GitHub webhook (optional, or polling)
        ↓
ArgoCD detects changes
        ↓
ArgoCD compares git state vs cluster state
        ↓
If different: ArgoCD syncs to match git
        ↓
Cluster state matches git (desired state achieved)
```

## Application Manifests

### Root Application (bootstrap-app.yaml)

This is created manually in Phase 7 via kubectl:

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: root-app
  namespace: argocd
spec:
  project: default
  source:
    repoURL: https://github.com/AlyBadawy/hl-beta
    targetRevision: main
    path: git-ops/root-app
  destination:
    server: https://kubernetes.default.svc
    namespace: default
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
```

**Key points:**
- **repoURL:** Points to our repository
- **path:** Points to root-app Helm chart
- **automated:** Continuously reconciles cluster to match git
- **prune:** Deletes resources removed from git

### Child Application Example (argocd-app.yaml)

Generated by root-app Helm templates:

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: argocd
  namespace: argocd
spec:
  project: default
  source:
    repoURL: https://argoproj.github.io/argo-helm  # External helm repo
    chart: argo-cd
    targetRevision: 7.6.0
    helm:
      valuesObject:
        # Values from git-ops/argocd/values.yaml
        server:
          ingress:
            enabled: true
            hosts:
              - argo.in.alybadawy.com
  destination:
    server: https://kubernetes.default.svc
    namespace: argocd
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
```

**Key differences:**
- **source.chart:** Uses external Helm repository (official ArgoCD)
- **source.helm.valuesObject:** Inline values OR references git values
- **destination.namespace:** Deploys to argocd namespace

## Configuration as Code

```
git-ops/ (in repository)
        ↓
```

## Adding New Applications

### Step 1: Create application directory

```bash
mkdir -p git-ops/my-app
```

### Step 2: Add Helm chart or manifests

Option A: Helm chart
```bash
helm create git-ops/my-app
```

Option B: Kustomization
```bash
# Create kustomization.yaml with custom resources
```

### Step 3: Create Application manifest

Add to `git-ops/root-app/templates/my-app-app.yaml`:

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: my-app
  namespace: argocd
spec:
  project: default
  source:
    repoURL: {{ .Values.git.repoUrl }}
    targetRevision: {{ .Values.git.targetRevision }}
    path: git-ops/my-app
  destination:
    server: https://kubernetes.default.svc
    namespace: my-app
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
    syncOptions:
      - CreateNamespace=true
```

### Step 4: Commit and push

```bash
git add git-ops/my-app git-ops/root-app/templates/my-app-app.yaml
git commit -m "Add my-app to root application"
git push origin main
```

ArgoCD automatically syncs the changes within minutes (or immediately with webhooks).

## Syncing and Reconciliation

### Auto-sync Settings

Current configuration uses aggressive auto-sync:

```yaml
syncPolicy:
  automated:
    prune: true      # Delete resources not in git
    selfHeal: true   # Correct drift caused by manual changes
```

**Implications:**
- ✓ Cluster always matches git state
- ✓ Manual kubectl changes are reverted
- ✗ No manual overrides possible
- ✗ Accidents are harder to recover from (but reversible via git)

### Manual Sync

You can also trigger sync manually:

```bash
# Sync a specific application
argocd app sync root-app

# Via ArgoCD UI
# Login → root-app → Sync button
```

## Troubleshooting

### Application not syncing

Check Application status:
```bash
kubectl get applications -n argocd
kubectl describe application root-app -n argocd
argocd app list
argocd app get root-app
```

### Git sync errors

Check if git URL is correct:
```bash
kubectl get configmap git-config -n cluster-config -o yaml
```

Check ArgoCD logs:
```bash
kubectl logs -n argocd deployment/argocd-repo-server
```

### Manual changes reverted

This is expected with auto-sync enabled. To preserve manual changes:
1. Disable auto-sync temporarily
2. Make changes
3. Update git
4. Re-enable auto-sync

Or just ensure all changes are made in git first.

## Best Practices

1. **Always commit before sync** — Ensure git is the source of truth
2. **Use Helm or Kustomize** — For DRY configuration management
3. **Separate concerns** — Different apps in different directories
4. **Version your charts** — Use semantic versioning for Helm charts
5. **Document changes** — Commit messages should explain why
6. **Test changes locally** — Use `helm lint` or `kubectl apply --dry-run`
7. **Review PRs** — Use GitHub PRs before merging to main
8. **Monitor sync status** — Watch ArgoCD UI for deployment progress
